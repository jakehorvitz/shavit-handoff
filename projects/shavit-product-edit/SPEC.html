3Contact form → lead flow

Browser

React form (name/email/phone/message) + Turnstile widget + hidden honeypot. On submit: get Turnstile token, POST JSON to the Edge Function URL. Only the Supabase anon key + Turnstile site key ship in the bundle.

Supabase Edge Function

(1) verify Turnstile token server-side; (2) reject if honeypot filled; (3) validate/sanitize fields; (4) rate-limit by IP; (5) insert into leads using service_role (server env only); (6) call Resend to email Shavit. Returns clean success/error JSON.

Postgres leads

Columns: id, created_at, name, email, phone, message, ip, user_agent. RLS enabled, zero public policies → anon key can't read/insert/update/delete directly. Only the Edge Function (service_role) writes.

Secrets

Never in bundle: service_role key, Resend API key, Turnstile secret key. These live only in Supabase Edge Function env vars.

7Cutover runbook — email-safe, direct hardened by Stage-4 review

  1. Capture the zone first. Before any edit, export/screenshot the full Squarespace DNS zone and run dig shavitrootman.com MX +short, dig TXT +short, dig _dmarc.shavitrootman.com TXT +short, and the GoDaddy DKIM selector. Record the current Hostinger A value 195.35.39.73 (rollback target).
  2. Lower TTL 24–48h ahead. Set the apex + www record TTLs to 300s in Squarespace (default is often 4h) so a bad flip — or rollback — propagates in minutes.
  3. Build + Supabase + Turnstile + Resend wired; validated on temporary *.netlify.app URL (a real test lead lands in Shavit's inbox; Lighthouse/axe green).
  4. In Netlify, add shavitrootman.com + www as a custom domain using EXTERNAL DNS ONLY — never "Netlify DNS" / nameserver delegation. Delegating nameservers would drop the GoDaddy MX + SPF/DKIM/DMARC and bounce all email. Keep nameservers on Squarespace/Google.
  5. Also confirm the Squarespace domain is not toggled to "connect to a Squarespace site" — that can override apex records.
  6. In Squarespace DNS, change ONLY two records: delete the apex A → 195.35.39.73 and set apex ALIAS @ → apex-loadbalancer.netlify.com (Squarespace supports ALIAS; use the fallback A → 75.2.60.5 only if ALIAS is rejected). Set www CNAME → <site>.netlify.app. Canonical = apex; 301 www→apex in Netlify. Touch zero MX / TXT records.
  7. Wait for propagation + Netlify TLS provision. Verify (all of): HTTPS live + valid cert, every route loads, contact form delivers a lead, and three email tests — (a) external → info@ arrives, (b) info@ → external lands in inbox not spam, (c) dig MX/TXT byte-identical to the pre-flip capture.
  8. Kill Hostinger LAST. Leave the WordPress site running 48h after a fully-verified flip (it's the rollback target and serves stragglers still caching the old record). Rollback = delete ALIAS, re-add A → 195.35.39.73.
  9. Post-cutover: submit sitemap to Google Search Console; check Squarespace DNS for DNSSEC and enable if available.

9Acceptance criteria Stage 5 build gate

The build loop only passes when an executable check confirms all of these. This is the machine-verified gate — "looks done" won't pass it.

  1. npm run build exits 0 and emits dist/ with a separate HTML file per route (index.html, companies.html or companies/index.html, etc.).
  2. Zero occurrences of Invest With Me, accredited-investor copy, or investment-amount fields anywhere in dist/.
  3. Zero occurrences of stray brand strings that should be "Charger Realty Management" in nav/footer/intro/titles (subsidiary names on Companies page exempt).
  4. No unpkg, no @babel/standalone, no react.development.js referenced in built HTML.
  5. No uploads/ dir in dist/, and zero Google Forms footprint: no docs.google.com/forms, no PLACEHOLDER_ IDs, no Forms.jsx, no "Open in Google Forms" text anywhere in dist/ or the source tree.
  6. Each route's HTML contains a unique <title> + meta description + canonical; sitemap.xml + robots.txt present; Organization/LocalBusiness JSON-LD present.
  7. _headers present with CSP + nosniff + referrer + frame protections.
  8. No service_role, Resend, or Turnstile secret key string anywhere in dist/.
  9. Lighthouse accessibility ≥ 95 and zero axe serious/critical on / and /contact.

11Build toolchain Stage-4 council addendum

Two adversarial reviewers pressure-tested the plan. DNS findings folded into §7. Build findings below.

Toolchain (locked)

Vite + React 18 + react-router-dom v6 + vite-react-ssg for prerendering. vite-react-ssg runs renderToString in Node (effects never fire → clean, animation-free markup). Rejected: react-snap (unmaintained, Puppeteer-crawls the live 4.6s intro into the HTML), Astro (would force rewriting components into islands).

The conversion (mechanical, ~all 17 files)

  • Strip each file's window.X = X / Object.assign(window,…) footer and /* global … */ banner → real export + import. Replace const { useState: useAppState } = React aliasing with import { useState } from 'react'.
  • Extract the data globals (SHAVIT_PHOTOS, STOCK, URLS, HERO_VIDEO, CONTACT) — currently defined in Shared.jsx — into a data.js module and import where used. (Note: reviewer flagged these as "missing" — false alarm, they're in Shared.jsx; just need extracting.)
  • Good news: every browser-API call (IntersectionObserver, matchMedia, scrollY, rAF, video) is already inside useEffect/handlers → SSR-safe, nothing crashes at prerender once the window-footers are gone.

Two prerender traps to fix

  • LogoIntro (4.6s black curtain) must be client-only (mounted-guard returning null on server) — otherwise every prerendered page ships a black overlay as the first thing Google/users see. Add a reduced-motion guard too.
  • Hero <video autoPlay>: add a poster= image so first paint is an image (LCP), lazy-init the video, and don't autoplay under prefers-reduced-motion.

Router change

Replace App.jsx's hash-switch with a real route list (/, /companies, /case-studies, /meet, /contact, /accessibility) driven by vite-react-ssg → emits companies/index.html etc. with real crawlable text (today the site ships an empty <div id="root"> to crawlers).
