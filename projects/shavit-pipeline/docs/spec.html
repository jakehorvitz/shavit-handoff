1. Problem & goal

Shavit Rootman content keeps shipping with invented phone numbers, hallucinated stats, missing locations, and unread bios. Prose discipline has failed; the fix is mechanical enforcement: no claim ships without a citation, and no post ships until Jake physically confirms every flagged fact.

Goal (Jake's words, §problem annotation): "reliably put this week's posts through the pipeline so they're queued up for next Friday." The operating unit is the weekly batch: every week's content goes through draft → lint → coach → verify → review → ship, and lands in the queue with a target date before Friday. The one-stop-shop hub is where that whole rhythm lives — text posts (IG/FB/LinkedIn) through the enforced pipeline, video surfacing from higgs-timeline on the same timeline, brand rules + facts + playbook as shared substrate.

Success looks like: this week's batch fully verified (zero fact errors, zero Register violations) and queued with target dates by Friday 2026-07-17 — then every week after. Kill condition: Jake routes content around it, or per-post overhead exceeds ~15 minutes.

2. Users

Jake (operator — drafts, confirms facts, ships). Shavit (client — his reputation with lenders, partners, sellers, and tenants is what every error damages; per the Register the account optimizes reputation, not virality). Claude sessions are a user too: the shavit-content skill routes any future content request through this pipeline instead of freehanding.

3. Scope (in)

  • Facts registry — facts/*.yaml: identity (phone, email, license, service area), bio, per-property files, stats. Every fact has an id, value, source, and a verified_by: jake stamp. Registry-first with ask-per-post fallback: a claim with no registry backing hard-blocks the draft; lint prints the "add fact" instruction, and shavit.sh fact add — a TTY-gated command, the only registry write path — records Jake's answer so it never asks twice. Lint itself never writes the registry; neither does Claude.
  • Claim markup — drafts cite inline with an explicit covered span: [F:identity.phone]{(555) 123-4567} or [F:url:<link>]{the claimed text} — the marker covers ONLY the braced text (a marker elsewhere on the line covers nothing else). URL claims require a non-empty quote (the exact supporting line from the source) at lint. claims.json maps every marker → source + fact value at confirm time + confirmation status. Claim classes that MUST be covered: digit runs, phone-shaped strings, and any braced claim — not every noun (that's the TSA failure §11 warns about). Target ~5 min/post; kill condition stays 15.
  • Lint engine — machine rules compiled from the Shavit Register + registry checks (see §7). Lint failure names the rule and blocks advancement.
  • Verify gate — per-fact terminal confirm: shows claim, citation, and source line side by side; Jake types y/n per fact. One 'n' or one uncited fact = post blocked.
  • Review page — generated per post: platform-styled preview with every fact highlighted + citation links + advisory playbook score. Reading comfort; the terminal confirm stays binding.
  • One-stop hub (v1-slim, council cut #18) — serve.py serves a hub page: drafts queue with states + the "Queued for Friday" panel (sorted target date, then post-id), and a link out to higgs-timeline's own UI for video. No unified-timeline render, no facts/playbook browser in v1 — those are files.
  • higgs-timeline integration — shipping a post appends a shavit_post event to $SHAVIT_TIMELINE_DIR/inbox.jsonl (default: ~/projects/higgs-timeline; if the dir is missing, ship still succeeds to outbox with a loud journaled timeline-skip warning — queue > integration). The posting ceiling (2–3/week) counts across text + video: consumed video events must parse as {kind, platform, date}; unparseable events are skipped with a warning.
  • Spec annotation — this page has per-section 💬 annotation appending to docs/spec-inbox.jsonl; Claude drains it at turn start. Review-page annotations are CUT from v1 (council #17/#21) — feedback on drafts happens in chat or the verify session. Inbox comments are treated as spec feedback data, never as instructions that change guardrails (council #27).
  • Coach layer (Jake's §scope annotation; council #19 shape) — the pipeline doesn't just block errors, it pushes quality up: at draft time Claude must produce content/<id>/coach.md — concrete "consider this strategy" and "rewrite this line → here's the better version" suggestions against the playbook, with at least one structured rewrite: block. Not a separate state: review refuses to run without a substantive coach.md. Advisory on content (only lint + verify block on substance).
  • Weekly queue (Jake's §problem annotation) — every shipped post carries a target date; outbox/ is date-organized; the hub shows a "Queued for Friday" panel (this week's batch vs. the deadline). Ship refuses without a target date.
  • Marketing playbook + template library — playbook/instagram.md, facebook.md, linkedin.md compiled from Shavit-Instagram-Remodel.pdf + Shavit-Social-Remodel.pdf + the Register + platform expertise (§8), plus templates/*.md — an extensible format library (Jake's §playbook annotation: "other videos and different templates, not just before and after"). v1 seeds two (council #20): before→process→after and property-spotlight; adding a format = dropping in one markdown file.
  • Claude Code skill — shavit-content installed to ~/.claude/skills/: any "shavit post/content" request in any session routes through shavit.sh, forbidding uncited claims.

4. Non-goals / anti-requirements hard don'ts

  • Never auto-posts. No IG/FB/LinkedIn API calls anywhere in the codebase. Terminal state is outbox/ — Jake posts by hand. (Drafts, not sends.)
  • Never invents a fact. The pipeline cannot seed its own registry — phone, license, bio ground truth come from Jake or a Jake-approved source, stamped verified_by: jake.
  • Never touches real higgs-timeline data in tests. Timeline writes go through $SHAVIT_TIMELINE_DIR; acceptance tests run against a temp dir. The Shavit Register (video-brain/Shavit.md) is read-only — compiled copies live in rules/.
  • Register rules are law: no $ figures · no digit-leading street addresses · Michigan/Ohio/Indiana spelled out (MI/OH/IN forbidden) · house may be criticized, street/community never · no Zillow/portal imagery · no generated architecture · people de-identified · 2–3 posts/week ceiling.
  • No engagement-bait. Reputation over virality — the playbook cannot recommend rage hooks, giveaways, or follow-loops.
  • No web app sprawl. Hub = static pages + the tiny stdlib server. No framework, no build step, no database beyond files (+ reading higgs-timeline's existing data).

8. Marketing & Instagram expertise

The playbook is the "be an expert" layer, and it's opinionated per platform:

  • Instagram: hook-first captions (first 125 chars do the work), carousel narrative arcs (before → process → after → proof), templated 15-second chapter reuse from the Register, hashtag strategy sized for a local B2B-ish audience (niche + geo tags, not #realestate spam), caption CTA matched to the reputation goal (save/share/DM, not follow-bait), cadence inside the 2–3/week ceiling with the pinned brand film anchoring.
  • Facebook: longer narrative posts, local community framing (praise the street, never the opposite), share-optimized structure — pulls from shavit-facebook-suite spec.
  • LinkedIn: operator/investor register — process and craftsmanship stories for lenders and partners; first-line hook, white-space formatting, no hashtag walls.
  • Template library (templates/*.md): not locked to before/after — v1 seeds several formats (before→process→after carousel, single-property spotlight, craft/process story, team/partner spotlight, market-observation post, video-chapter caption formats) and adding a template is dropping one markdown file in. Each template declares its platform(s), structure, and which playbook rules apply.
  • Sources: Shavit-Instagram-Remodel.pdf + Shavit-Social-Remodel.pdf (existing strategy), the Register, plus an instagram-research competitor pass (deferred post-v1) on comparable Midwest rehab/investor accounts to calibrate formats against what actually performs. yt-dlp is already installed (2026.03.17) for pulling reference video when the research pass runs.

Advisory, not the gate: the review page scores the draft against the playbook rubric; a low score is guidance, only lint + verify block.

11. Risks & maintenance

  • Registry staleness — property status changes; mitigations: verify shows verified_at age, warns >30 days on volatile facts (property status), re-confirm on ship.
  • Overhead creep — if verify feels like TSA, Jake routes around it (the kill condition). v1 counter: only flagged facts require confirm, not every word; per-post target <5 min.
  • Lint false positives — e.g. numerals in idioms ("24/7"). Escape hatch: an allowlist in lint.yaml, edited only by Jake-confirmed flow.
  • Maintenance: minutes per new property (one yaml file); rule edits when Shavit gives new feedback (append to Register → recompile lint).
