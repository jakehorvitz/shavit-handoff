2The listings data model (the core new thing)

Weekly content from Shavit's Drive must become a listing with zero layout work.

// site/src/properties.js
export const PROPERTIES = [
  {
    id: 'budlong-street',
    state: 'MI',                      // MI | OH | IN
    status: 'available',              // available | coming-soon | hidden
    name: 'Budlong Street',
    locale: 'Hillsdale',
    type: 'Single-family',            // free text: 'Duplex · 2 units', 'Furnished · 30–180 days'
    line: '3-bed near downtown Hillsdale — everything new inside.',  // destination + timeline, not renovation pride
    rent: 1150,                       // REQUIRED for available (council H1: omitting price kills tenant conversion)
    beds: 3, baths: 1,
    available: 'now',                 // 'now' | 'Aug 1' — the time-delay lever
    eta: null,                        // coming-soon only: month-level, e.g. 'September' (never bare "Coming Soon")
    photo: '/assets/listings/budlong-street.jpg',   // uniform house-front crop, ≤250KB
    cta: 'ask'                        // ask | notify (label + sms body vary)
  }, ...
]
// Cards render a chip row: "$1,150 · 3bd 1ba · Move in now" — three data points, zero prose.

Hidden ≠ filtered (council T2 — BLOCKER fix). Vite bundles the whole imported array into dist JS, so status:'hidden' entries WOULD ship as strings. Staged listings therefore live in site/src/properties.staged.js — never imported — with photos in site/staging-assets/ (outside public/). Publishing = move the entry + move the photo. The dist sweep checks file NAMES under dist/assets/listings/ too, not just bundle strings.

  • State sections render from this array; empty status groups collapse (no "Coming soon" header with zero cards).
  • status:'hidden' keeps an entry staged without publishing — matches Shavit's "only what I say goes up".
  • Photos: one uniform house-front hero per listing at /assets/listings/<id>.jpg, 4:3 crop, consistent treatment (match IG/FB border/color system). Processed from Drive uploads.
  • Card CTA: sms:+18053644415&body=Hi — asking about {name} ({locale}) and tel: fallback. Every inbound identifies the property.
  • Seed content (launch set, pending Shavit confirmation via asks-list): MI — Budlong, 34 Mead, 61 Salem (available); 43 Howder Duplex, The Trio, 60 S Norwood (coming soon). OH — Larchmere, Cleveland Heights (available). IN — 2217 Parkview (available); 1114 Cedar, 1902 E Ewing (coming soon).

3"The Standard" — anonymized proof strip

Jake's gate-2 rider: must read fully legit. Hormozi: documented proof is uncopyable — keep it, anonymize it.

  • Aggregate counter band (approved numbers ONLY): 50+ doors · 3 states · $12M+ · 200 by 2030. Reuses existing Counter/StatsGrid components.
  • 2–4 before/after pairs: grayscale-dark "before" ↔ full-color "after", tags only (no addresses, no dates, no entity names). Captions are story-flavored one-liners ("Written off, brought back"), sourced from real Drive "Past Projects" photos.
  • Hard rule: nothing in this section may identify a specific parcel — no addresses, no street-recognizable wide shots paired with locality labels finer than the state.

Address policy (the whole-site rule — gate-3 amendment)

  • Addresses appear ONLY on active rental inventory (Available Now / Coming Soon) — information that is public the moment a home is listed for rent anywhere. A tenant cannot rent a home without its address; this is Shavit's own "one-stop shop" ask.
  • Never appears anywhere on the site: past/sold/held holdings by address, which entity owns which property, or any aggregate list from which total holdings could be reconstructed. Entity names appear only as the management face ("Managed by Charger Property Management"), never as owners.
  • When a listing leaves the market, its card flips to hidden — the address leaves the site with it.

  • Mobile: state sections and card grids readable at 375px; no horizontal scroll.
