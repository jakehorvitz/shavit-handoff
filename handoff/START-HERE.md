# Start here

This is the working handoff for the next person managing Shavit's website and content. You have the actual source files and designs, plus the context needed to choose among them.

## Your first hour

1. Read [the operating guide](OPERATING-GUIDE.md) and current [brand rules](../projects/shavit-pipeline/rules/brand.md).
2. Browse the [website/design guide](WEBSITE-AND-DESIGNS.md) and [media/editing guide](MEDIA-AND-EDITING.md). These identify the latest source, final candidates and older alternatives.
3. Restore the original media using the README command. Open the HTML specs locally, or run the project-specific review server. GitHub displays HTML source rather than executing a design.
4. Obtain collaborator access using [the access checklist](ACCESS-AND-TRANSFER.md).
5. Review [known gaps](KNOWN-GAPS.md), then reconcile the next deliverable and publication status with Jake and Shavit.

## How the archive is organized

`projects/` preserves the nine focused project folders. `deliverables/` preserves named Desktop handoff/export folders and field footage. `downloads/` holds the matching downloaded finals. `legacy/` preserves early strategy/analytics and proposal material. `editors/` holds discovered Palmier masters and their linked originals. `catalog/` records each included path, checksum, source, deliberate exclusion and source revision.

Binary assets live in private GitHub Release archives so the Git clone stays usable. The restore tool recreates them where the source expects them. Repeated copies are stored once in downloads, then reproduced in all original project locations.
